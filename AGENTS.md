# Student repository guidance

Students implement the assessed track and write their own analyses and report. Assistants may explain units, concepts, public documentation and environment errors, run existing public tests, or discuss one issue in a small student attempt.

Leave graded TODOs, adapters, training objectives, control loops, policies and recovery logic to students. Avoid submission-ready reports, patches or equivalent pseudocode. Preserve the public tests, budgets and sealed evaluation boundary. Never fabricate experiments or usage logs.

The in-course supervisor may use the specified model and tools within the evaluation budget. The shared numerical planner determines power and the evaluator settles one hour. Record framework versions and modifications in THIRD_PARTY.md. Keep course tool traces separate from coding assistance.

Record assistance and independent verification in AI_USAGE.md. Each member should explain their code and recompute a physical time step.
